# 前端公网访问（GitHub Pages / 免设置镜像）

## 一、现在就能用的地址（免设置，已实测）

```
https://raw.githack.com/YHSome/oj-ojojoj/main/frontend/
```

（`.../frontend/index.html` 同样可用；两种都实测会直接渲染出应用）

* 全 HTTPS → `crypto.subtle` 可用（非对称加密提交正常）；
* `index.html` 返回 `text/html`、`assets/*.js` 返回 `application/javascript`、`style.css` 返回 `text/css`（已逐个验证）；
* 跟随 `main` 分支，**每次 push 自动更新**（githack 有几分钟缓存）；
* 页面里**不含任何云端密钥**，访问者需要在「连接设置」里填自己的 TinyWebDB 实例。

同类可选：`https://cdn.jsdelivr.net/gh/YHSome/oj-ojojoj@main/frontend/index.html`、
`https://cdn.statically.io/gh/YHSome/oj-ojojoj/main/frontend/index.html`
（这两个把 HTML 当 `text/plain` 返回，**不能直接在浏览器渲染**，只适合取文件）。

## 二、Pages 没启用的真实原因（已定位，含我自己的失误）

曾经的 Actions 报错：

```
Branch "main" is not allowed to deploy to github-pages due to environment protection rules.
The deployment was rejected or didn't satisfy other protection rules.
```

实测证据：

| 检查 | 结果 |
|---|---|
| `GET /repos/YHSome/oj-ojojoj/pages` | **404 → Pages 从未启用** |
| `GET /repos/.../environments` | `github-pages` 已存在，`{protected_branches:false, custom_branch_policies:true}`，**白名单为空** |
| `main` 是否受保护 | `protected: false` |

**原因链**：我在 workflow 里写了 `environment: github-pages`，GitHub 于是**自动创建了这个 environment**；
自动创建时带上"只允许指定分支"的空白名单 → 任何部署在 **job 启动阶段**就被拒（所以表现为
"1 秒失败、一个 step 都没跑"），而不是运行到某一步才报错。

**我的修正**：删掉了那个 workflow（仓库不再产生红叉）。空 environment 留着无害，
但如果你以后还想用 Actions 部署，需要先按下面 B 把它白名单加好。

## 三、收尾（二选一，都需要一台能打开 github.com 的设备 —— 手机热点最省事）

### A. 分支部署（推荐：不碰 Actions、不涉及 environment 规则）

> Settings → Pages → **Source: Deploy from a branch** → Branch: **`gh-pages`** / **(root)** → Save

`gh-pages` 分支**已经推好了**（内容 = `frontend/` + `.nojekyll`）。设好后：

```
https://yhsome.github.io/oj-ojojoj/
```

以后前端改完，同步一次即可（会重建该分支并用 `-f` 强推）：

```bash
bash tools/publish_pages.sh
```

### B. 继续用 Actions 部署

> Settings → Environments → **github-pages** → Deployment branches and tags
> → 选 **All branches**（或 Add deployment branch rule 填 `main`）→ Save

改完告诉我，我把 workflow 加回来（内容与之前一致：checkout → configure-pages → upload `frontend/` → deploy）。

### C. 一条命令搞定 A（有 Personal Access Token 时）

```bash
curl -X POST -H "Authorization: Bearer <TOKEN>" \
     -H "Accept: application/vnd.github+json" \
     https://api.github.com/repos/YHSome/oj-ojojoj/pages \
     -d '{"source":{"branch":"gh-pages","path":"/"}}'
```
（token 需要 `repo`（经典）或细粒度里的 `Pages: read and write`）

## 四、当前网络下的注意事项

网页版 github.com 目前被 **SNI 级阻断**（详见 [GitHub无法访问怎么办.md](GitHub无法访问怎么办.md)）；
但 **`git push/pull` 走 SSH 一直正常**，`gh-pages` 分支也是这样推上去的。

所以现状是：
* **发布前端** → githack 立即可用；
* **别人拿代码** → `python tools/get_repo_zip.py --extract`；
* **正式 Pages** → 等你能上网时点一下开关（方案 A 一次点击即可）。
